商品可以按在售／预售状态与类型组合筛选，并按价格排序。卡面支持按名称、属性、类型和日期中的词语检索，多词以空格分隔；灯箱前后翻页与左右方向键遵循当前筛选和排序，Esc 关闭并恢复焦点。没有匹配结果时可一键清除筛选。留言示例单独标注，清空后可在当前页面撤销；刷新或新投递后撤销失效。浏览器存储失败会保留既有留言与输入内容并提示重试。

手机竖屏打开网站即进入独立的全屏 Live2D 舞台。侧边提供聊天、换装、表情、动作、上一套和下一套入口；各面板以紧凑的半透明底部浮层展开，可以收起到侧边，收起不清空对话。模型缩放以竖向控件显示在右侧“下一套”下方，依次为放大、当前比例、缩小、还原；小屏可上下滑动侧栏访问完整操作，展开聊天时侧边入口收起，缩放仍可独立调整，键盘出现时聊天面板会为缩放控件留出侧边空间；换装面板提供暂停和跟随鼠标，表情与动作单独展示当前模型的可选项；没有独立表情文件的演奏模型会显示说明。聊天正文为 13px，手机端移除四个快捷话题按钮、情绪状态行与设置说明标题行；模式、解锁和清空操作收纳到标题栏的聊天设置按钮，默认不占正文空间。密码弹窗也采用半透明材质。“网站”入口可退出舞台浏览资料和卡面，点击“和爱音聊聊天”返回全屏。手机键盘出现时对话面板适应可见高度，离开竖屏手机布局会恢复原有页面排布，保留当前模型、比例和聊天记录。新版互动界面仅适配手机竖屏；这里的全屏指浏览器可视区域，不要求浏览器支持原生 Fullscreen API。

其他手机页面保持正文 14px、辅助文字约 12px的紧凑排版；资料卡和卡面图鉴采用双列，手机横屏时为三列。输入控件保留 16px 字号，发送及模型操作等主要按钮保留 44px 点击高度。电脑端功能及模型默认缩放比例保持原有设置。

本地互动在浏览器内匹配关键词，不上传聊天内容。配置服务端密钥后可使用 DeepSeek AI：本条消息及最多最近 5 轮成功的 AI 对话经 Vercel 服务端发送到 DeepSeek，流式回复同时触发表情和动作。两种模式均为非官方同人演绎，聊天历史仅保留在当前页面内存；刷新、清空或切换模式会重置 AI 上下文。本站代码不将聊天写入数据库、浏览器持久存储或应用日志，服务提供商的数据处理以其政策为准。留言板和主题偏好仍保存在当前浏览器的 `localStorage`。

AI 对话不预设积极或开心倾向；根据爱音当前话语的主体、语义、否定与转折选择情绪，缺失或未知标签回退为平静。认真、思考、悲伤、愤怒、害羞与开心均按实际内容使用，表情与动作同等考虑，不直接复制访客或被引用人物的情绪。上传的角色人格原文保持不变。

同一次 AI 回复可在自然语气转折时切换情绪。播放器按服装映射实际动作，预热常用资源，下一段开始前等待当前动作与表情淡变各自达到 80% 的播放进度，再自然衔接，文字与动作依序展示；按实际渲染进度及各素材时长计算，无法读取动作时长时等待真实结束，同一动作则沿用剩余播放而不强制重启；跨语气有多个匹配候选时，优先避开正在播放的同一动作与表情。长回复在自然句读处按实际进度延续同语气，最短间隔 1.2 秒，不再固定等 4.5 秒或续接三次即停止；等待回答时仅切换思考表情，避免长动作挤占首句。暂停、离屏、换装或取消会释放等待，避免播放队列卡住。停止或重新锁定会取消尚未展示的文字和动作；网络已接收但还未展示完的轮次仍可停止。系统“减少动态效果”偏好下文字直接展示。分段情绪由模型判断，不能保证每次都准确还原角色。

聊天默认跟随最新文字；向上翻阅历史消息时停止自动滚动，有新文字会显示“查看最新回复”，点击后恢复跟随。中文输入法确认候选字时不会同时提交消息。

所有版本的聊天按语气建立动作、表情候选池，从模型实际拥有的同类动作、方向和表情中轮换；候选先按语义筛选，每组用完一轮后再重选；动作与表情的避重复评分为 1:1，不为增加利用率混入其他语义。较长回复在句读处、动作与表情均达到 80% 后衔接同语气的下一动作，不在该进度前打断，不再限制为单轮三次。手动动作按钮保持精确选择，停止、清空或锁定后回到待机；减少动态效果模式不额外续接。候选池不会为了覆盖率把哭泣、生气等动作放进开心对话，也不使用含义不明的动作。

**启用 AI：** 在 Vercel 项目环境变量中设置 `DEEPSEEK_API_KEY` 并重新部署。密钥仅在服务端 AI 聊天及语音日语转换中使用，禁止放入前端脚本或提交 Git。AI 默认启用密码锁，访客需在提示框输入站长提供的密码；刷新或手动锁定后需重新解锁，本地互动不受影响。默认密码仅保存服务端加盐摘要，可用 `CHAT_ACCESS_CODE` 覆盖；解锁验证不调用模型，每次聊天仍在服务端验密。完整配置、限流边界与验证步骤见 [DeepSeek 接入说明](docs/DEEPSEEK.md)。

**联网搜索：** 默认关闭，可在对话设置中手动开启。复用现有 DeepSeek 密钥，通过原生联网工具按问题检索；最新消息、日程与商品信息要求先查证，普通闲聊无需每轮搜索。查到信息后，爱音结合上传的人格设定表达看法，区分检索事实与个人评价。实际检索后显示可展开的来源链接，没有检索结果时不标记为已联网查证。搜索可能增加等待时间和API用量，Live2D表情动作衔接、密码锁及本地互动继续保留。

**爱音语音：** 完整 AI 回复可点击“播放日语”，先由 DeepSeek 将单条回复转成日语，再以爱音的同人合成音色播放；聊天原文、历史和 Live2D 联动保持不变。姓名使用「ちはや あのん」的假名读法，朗读按句意编排情绪强度、表达方式与适量停顿，不默认开心；角色演出依据与调优边界见[语气参考记录](docs/VOICE-REFERENCES.md)。自动朗读默认关闭，可在聊天设置中开启。Vercel 需配置 `FISH_AUDIO_API_KEY`，复用已有 `DEEPSEEK_API_KEY` 做日语转换；Fish Audio 使用公开爱音音色和免费开发者模型，不自动转为付费模型，日语转换调用按 DeepSeek 账号计费。支持停止、重播及本页音频缓存，翻译或合成失败不影响文字聊天，也不回退朗读中文。配置与当前免费政策见[语音接入说明](docs/VOICE.md)。

AI 人格主体采用站长提供的 `anon.txt` 全文，人物经历、关系和称呼表原样接入服务端提示词；Live2D 情绪与输出协议单独保留。人格原文与文件哈希的回归检查用于避免导入遗漏或改写。

Live2D 控制区提供“跟随鼠标”开关，默认开启。关闭后恢复正向视线；开关偏好保存在当前浏览器，换装、重新加载与刷新后继续生效，不影响对话、动作和表情按钮。

手机竖屏打开就是全屏舞台，画布会一直占着 GPU，所以播放器按交互强度分档限帧：手机待机 30fps、触发动作或表情后 8 秒内 60fps、连续 90 秒无任何操作降到 15fps；点击、键盘、滚轮或重新滚回视口都会立刻恢复。桌面档位为待机 60fps、省电待机 30fps。分档只改绘制频率：PIXI 节流跳帧时不会推进 `lastTime`，下一帧的 `deltaMS` 会累积，因此动画速度不受影响。帧率与像素预算都是 `assets/js/live2d-viewer.js` 顶部的常量，可按机型再调。除限帧外还关闭了 MSAA（Live2D 是 alpha 混合贴图，抗锯齿对轮廓几乎无改善，却按采样数成倍放大填充开销），并把画布后备存储限制在手机约 100 万像素、桌面 260 万像素，高 DPR 手机因此不再按 2× 全屏渲染。舞台上的浮层（聊天面板、侧边按钮、缩放条、输入条）改用接近实色的底色替代 `backdrop-filter`，面板内部原有的半透明分层照旧：毛玻璃底在活动画布上会让浏览器每帧重算高斯模糊（Chromium 只在背景内容无变化时才复用模糊结果），而这层模糊在近实色底上几乎看不出来。

模型区可在 50%–200% 范围内按 10% 步进放大、缩小。手机首次打开时所有模型默认 150%，随后换装沿用本页最近一次手动设置的比例，“还原”回到 150%；刷新后重新从 150% 开始。电脑端仍按来源默认比例：bdon.moe / Our Notes 为 180%，Bestdori 为 100%，切换另一模型时采用其来源默认值。同一模型重载、暂停恢复保留手动比例；手机和电脑尺寸之间切换分别保留各自的比例状态，暂停时也可缩放。Bestdori 的 17 套都是游戏内拆包模型，动作 41–43 个、独立表情 28 个，共用 `037_general` 的通用动作与第一张贴图；卡面服装的按钮提示会写明对应卡名、服装编号与实装日期。Our Notes 的 8 套剧情模型各有 66 个动作与 36 个表情；吉他演奏款有 9 个舞台动作，无独立表情，聊天按语气自动选用真实演奏、舞台及收尾动作，徽章显示实际动作名称，无需说出动作关键词。bdon 剧情模型的普通中性聊天使用轻点头与平静表情，演奏模型使用平缓演奏；初始化、清空和手动待机仍恢复原待机，不将中性语句改为开心，也不随机使用汗滴或持续闭眼。动作播完自然回到待机。同 ID 跨索引仅导入一次，同款低清副本不重复加入，眼镜与无眼镜款分别保留。

模型区进入视口后才开始加载，后台标签页延后首次加载；暂停、离屏或切到后台时停止继续预热动作，恢复后接续。支持浏览器省流量设置时不额外预热。换装完成后释放已不用的旧贴图，快速切换时保留仍被当前模型共用的资源。

## 本地运行

页面使用静态 HTML、CSS 和原生 JavaScript，无需 npm 安装或构建；可选 AI 接口使用 Vercel Node.js Function。在仓库根目录启动 HTTP 服务可测试页面与本地互动：

```sh
python3 -m http.server 5173
```

打开 [http://localhost:5173](http://localhost:5173)。Windows 可按本机 Python 安装情况将 `python3` 换成 `py` 或 `python`。

Python 静态服务器不运行 `/api/chat`，因此本地互动正常、AI 选项不可用。需要本地联调接口时使用 `vercel dev`，服务端环境变量配置见接入说明。

Live2D 需要通过 HTTP/HTTPS 读取模型，不能依赖双击 `index.html` 的 `file://` 方式运行。模型和图片随仓库部署；Live2D 运行时从 CDN 加载，因此该模块仍需要网络和支持 WebGL 的浏览器。

更新官方资料或商品时，核对官方原页、含税价格和可购状态，再修改 `assets/data/anon-official.js`、对应商品图片及 `checkedAt`。不要将未知库存标为在售，也不要直接把 Shopify 接口的税前内部金额用作展示价。保留商品原名、原图地址与官方购买链接。

更新百科内容时，同步修改 `assets/data/anon-wiki.js` 和 [docs/SOURCES.md](docs/SOURCES.md)，保留页面修订版本、贡献者署名及许可链接；赛事赛季与消息发布日期应分别核对。`wiki.posters` 的每条要用「年份 + 赛事」能命中一条 `wiki.honors`，成绩取该荣誉的子串；海报图是第三方赛事素材，重新下载时同步更新 [docs/SOURCES.md](docs/SOURCES.md) 的来源与版权说明。

更新音乐作品时，先核对官方 discography 的标题、发售日与封面，再修改 `index.html` 里的音乐卡片。读法以官方公布和日本媒体整理的读法清单为准，不要凭字面猜读；还没有 MV 的新作给出检索入口，不发散到未核验的视频链接。

```sh
python3 scripts/fetch_discography_covers.py
```

- `fetch_bestdori.py` 抓取角色资料、卡面与立绘，原始 JSON 和清洗结果写入 `data/bestdori/`，图片写入 `assets/img/`。
- `build_site_data.py` 根据本地清洗结果生成 `assets/data/anon-cards.js`，此步骤可离线执行。
- `fetch_live2d.py` 先用角色接口（季节服装）与资源索引 `api/explorer/jp/assets/_info.json`（全部 `037_` 开头的 Live2D 包）列出服装，再用服装接口 `api/costumes/all.5.json` 取卡面名、服装编号与实装日期作为标签，最后按 `buildData.asset` 清单下载资源、组装 Cubism 2.1 `model.json` 并生成 `assets/data/anon-live2d.js`。只放通用动作、没有 `buildData` 的包（如 `037_general`）记为跳过并写进清单的 `bestdoriCatalog.skipped`。
- `fetch_discography_covers.py` 读取 BanG Dream! 官方 `discographies` 列表页，抓取 MyGO!!!!! 单曲与专辑封面，生成 `assets/img/music/`（640px JPEG）与 `assets/img/music/thumbs/`（320px WebP）；加 `--offline` 可用 `data/discography/raw/` 缓存重新生成尺寸版本。
- `node scripts/fetch_bdon_live2d.cjs` 合并 bdon.moe 剧情与演奏两个索引，按模型 ID 发现爱音全部不同款式；排除有标准版的同款 `_low` 副本，将真实 Unity 曲线、表情与物理转换为标准 Cubism 文件。索引与模型清单每次联网刷新，内容哈希资源复用缓存；加 `--offline` 可从 `/data/bdon/` 重建。两种模型抓取脚本会保留另一来源的服装选项与 bdon 去重清单。
- `node scripts/fetch_chat_font.cjs` 重新获取固定版本 Noto Sans SC 粗体与许可，校验上游字体哈希。访客加载本地 `unicode-range` 字体分段，无需请求字体 CDN。

两个抓取脚本默认跳过已存在文件，加 `--force` 可重新下载；资源会按日服、国服目录尝试，缺失素材不会被当作有效图片。重新抓取后的数量取决于上游实际数据，提交前应重新检查。Live2D 的 `idle` 分组仅放待机动作，41 个可触发动作放在 `reaction` 分组，避免待机时随机播放哭泣或生气。

## 部署与忽略规则

仓库已连接 Vercel，推送到 `main` 后自动部署至 [https://anon.srakhiumeow.top](https://anon.srakhiumeow.top)。`vercel.json` 保留空构建命令与仓库根输出目录，`api/chat.js` 和 `api/tts.js` 自动部署为 Node.js Function；未配置密钥时仍可使用静态页面及本地互动。部署完成后刷新页面查看更新；若旧资源仍被缓存，可强制刷新。

```sh
git add -A
git commit -m "说明这次改了什么及原因"
git push origin main
```

`.vercelignore` 排除根目录原始数据、抓取与检查脚本、文档及本地工具目录。站点所需的 `index.html` 和 `assets/` 必须入库并参与部署。

**`.gitignore` 与 `.vercelignore` 中的原始数据规则必须写成 `/data/`。** 不带根目录锚定的 `data/` 会误排除 `assets/data/`，导致线上卡面、商品或其他数据无法加载。现有生成数据随仓库保存，运行网站不需要先执行抓取脚本。
